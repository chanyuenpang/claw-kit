# Claw Kit 核心工作流

会话、计划任务、宿主调度与知识收尾

- Canonical 计划 → 执行证据：触发：knowledge finalizer 审查结束计划。参与者：source plan reader。状态变化：goal、requirements、retrospective 与 key decisions 成为证据上下文。条件/例外：task 列表和状态只解释 scope，不单独证明实现结果；freshness 冲突必须形成 no-edit 或谨慎更新。证据：.claw/truth/features/codex-knowledge-capture-boundary.md。
- Canonical 计划 → 计划任务：触发：计划创建、start 或 task list 更新。参与者：plan document 与 planning contract。状态变化：计划保存有序、可验证的任务检查点及其进度。条件/例外：任务进度只能在 process.\* 状态修改；task status 只表示流程进度，不证明业务结果。证据：packages/core/src/plan.ts；.claw/truth/features/cli-guided-workflow.md。
- Canonical 计划 → 工作流指引：触发：计划创建、变更、同步或恢复完成。参与者：buildPlanWorkflowGuidance。状态变化：根据当前/前一 plan status、未完成任务、template guidance、completion hooks 与 scope 派生 stage、nextsteps、nextTask、notes 和 commandHints。条件/例外：commandHints 仅是语法辅助；process.discussing 与 process.wait 均暂停执行；end.completed 和 end.leave 使用不同收尾语义。证据：packages/core/src/workflow-guidance.ts。
- 执行证据 → 知识写入器：触发：writer claim 成功并冻结 source plan/report 输入。参与者：builtin governance、external skill 与可选 doc updater assignments。状态变化：只用材料中的明确结论判断新增稳定知识、冲突与文档影响。条件/例外：无 durable conclusion、freshness 冲突或无新增知识时必须形成 evidence-backed no-edit；不能把任务状态当作事实。证据：.claw/truth/features/codex-knowledge-capture-boundary.md；packages/core/src/knowledge-assignments.ts。
- 宿主动作 → 宿主目标与进度：触发：adapter 成功执行受限宿主动作。参与者：宿主 Goal/Progress 工具。状态变化：process plan 创建或恢复 Goal 并投影任务进度；end.\* 清空 progress 并完成 Goal。条件/例外：这是 canonical plan 的幂等投影；失败不能回滚或否定计划 mutation。证据：packages/cli/src/codex-host-actions.ts buildCodexHostActions()。
- 宿主适配器 → 宿主动作：触发：command envelope 携带已验证的 v1 hostActions。参与者：支持 host actions 的 adapter。状态变化：adapter 按 action ID 至多一次消费 update_plan、create_goal 或 update_goal。条件/例外：没有 actionIdPrefix 时不生成动作；非能力宿主不消费；效果失败以结构化诊断返回。证据：packages/cli/src/codex-host-actions.ts；packages/cli/src/command-service.ts。
- 宿主适配器 → 知识写入器：触发：adapter 接受有效 knowledge dispatch 或 background runner 获得可执行作业。参与者：宿主原生 subagent/runtime。状态变化：启动内部 delegate plan，依次执行 claim、assignment subplan 与单次 knowledge done。条件/例外：CLI/Core 不托管 Codex/OpenCode writer runtime；fire-and-forget 回执不等于 writer 成功。证据：.claw/truth/features/host-neutral-integration-contract.md；.claw/truth/features/dsh-knowledge-dispatch-and-finalization.md。
- 宿主集成档案 → 宿主适配器：触发：adapter 接入 claw-kit 或处理一次命令效果。参与者：Core capability contract 与平台 adapter。状态变化：profile 声明允许的 Goal、恢复、report capture 和 knowledge finalization 能力，adapter 提供对应原生实现。条件/例外：CLI/Core 保留 canonical 语义，不嵌入平台 writer runtime。证据：packages/core/src/integration-contract.ts；.claw/truth/features/host-neutral-integration-contract.md。
- 宿主集成档案（supports-native-subagent-finalization=true） → 知识派发：触发：subagent knowledge job 已物化且当前 host 支持原生子代理收尾。参与者：resolveHostIntegrationProfile 与 dispatch builder。状态变化：profile 决定使用普通 delegate dispatch 或 atomic dispatch，并规范 Goal 指引、capture 与 compact 行为。条件/例外：不支持该能力的 host 必须拒绝 subagent policy，不能悄悄降级。证据：packages/core/src/integration-contract.ts；packages/cli/src/command-service.ts finalizeEnteredEnds()。
- 宿主集成档案 → 工作流指引：触发：Core 为指定 invocation host 构造 guidance。参与者：resolveHostIntegrationProfile 与 guidance builder。状态变化：按 capability profile 决定是否抑制 agent Goal 字段、是否提供恢复和 compact notes 等宿主差异。条件/例外：profile 是封闭且版本化的 v1 合同；不支持的 host 或版本不匹配必须显式失败。证据：packages/core/src/integration-contract.ts；packages/core/src/workflow-guidance.ts。
- 知识派发 → 宿主适配器：触发：终态 command envelope 返回 knowledgeDispatch。参与者：当前平台 adapter 或受合同约束的 Lead。状态变化：把 dispatch prompt 原样交给宿主指定的一次性 finalizer 路由。条件/例外：派发被接受后主线程立即结束，不等待或轮询 worker；自动派发宿主不得重复启动。证据：packages/core/src/knowledge-assignments.ts KNOWLEDGE_DISPATCH_LEAD_INSTRUCTION；.claw/truth/features/host-neutral-integration-contract.md。
- 知识收尾作业（execution-policy="subagent"） → 知识派发：触发：终态 mutation 已持久化带 finalizeId 和 jobPath 的 subagent ready job。参与者：buildKnowledgeDelegateDispatch 或 buildKnowledgeAtomicDispatch。状态变化：生成 preferReuse=false、包含固定内部模板与原样 prompt 的 immutable knowledgeDispatch。条件/例外：background policy 不在终态 mutation 返回该 dispatch；dispatch 不承载 writer 结果。证据：packages/core/src/knowledge-assignments.ts；packages/cli/src/command-service.ts。
- 知识写入器 → 项目知识：触发：全部 knowledge assignments 在 claim token 下完成。参与者：knowledge writer 与 consistency-aware governance。状态变化：新增或更新受边界约束的 Truth、ADR、索引和受管外部文档，并持久化 job result 后标记 succeeded。条件/例外：允许幂等 no-edit；写回 result 失败必须保持可重试，不能伪造成功；知识收尾不自动 Git commit。证据：.claw/truth/adr/hook-owned-two-phase-knowledge-finalization.md；.claw/truth/features/codex-knowledge-capture-boundary.md。
- 计划完成事件 → 执行证据：触发：root plan 正常完成。参与者：foreground closeout。状态变化：plan retrospective、durable key decisions 与最终回合内容补充任务级结论，形成收尾证据集合。条件/例外：achievement 只是前台完成信号，不代表异步知识 writer 已成功。证据：.claw/truth/features/cli-guided-workflow.md。
- 计划完成事件（scope="project"） → 知识收尾作业：触发：project-scope plan 从非 end.\* 进入 end.completed。参与者：tryEndKnowledgePlan 与 per-session registry。状态变化：派生稳定 finalizeId；background policy 记录 pending turn owner，subagent policy 立即持久化 queued、claim-mode ready job。条件/例外：session scope 不创建 job；subplan 完成并恢复 parent 时不为仍在运行的链路重复派发。证据：packages/core/src/knowledge-sidecar.ts tryEndKnowledgePlan()；.claw/truth/features/codex-knowledge-capture-boundary.md。
- 计划离开事件 → 知识收尾作业：触发：plan 进入 end.leave。参与者：tryLeaveKnowledgePlan。状态变化：清除 active/pending capture，并把同 session、同 plan 的 queued 或 running job 标为 expired，移除 assignments。条件/例外：leave 不创建新的 knowledge finalization，也不把取消当作延迟完成。证据：packages/core/src/knowledge-sidecar.ts tryLeaveKnowledgePlan()；.claw/truth/features/cli-guided-workflow.md。
- 计划离开事件 → 会话计划绑定：触发：计划进入 end.leave。参与者：focus/session binding store。状态变化：立即解除该 session 的当前 plan binding。条件/例外：soft close 只结束 live attachment，不等同于 leave；恢复到另一计划由显式 focus transition 另行建立。证据：packages/cli/src/command-service.ts；.claw/truth/features/task-layout-and-session-bindings.md。
- 计划变更 → Canonical 计划：触发：合法 plan/task mutation 进入持久化阶段。参与者：editPlan、ticket queue 与 file lock。状态变化：校验字段、状态迁移、retrospective 门和 stale snapshot 后更新 canonical plan，并产生初末状态归约事件。条件/例外：语法失败零提交；mutation chain 的首个语义失败保留此前成功步骤；后置宿主效果失败不回滚已提交计划。证据：packages/core/src/plan.ts editPlan()；.claw/truth/features/cli-guided-workflow.md。
- 计划变更（requested-status="end.completed"） → 计划完成事件：触发：plan.done 或等价 edit 请求 end.completed。参与者：Core status validator 与 completion hooks。状态变化：在全部完成条件和 retrospective 校验通过后记录 completedAt、plan_completed 事件及 completion hooks。条件/例外：project-scope 缺少 retrospective 时拒绝；subplan 完成会恢复 parent，只有 root 完成暴露 achievement。证据：packages/core/src/plan.ts；packages/cli/src/command-service.ts。
- 计划变更（requested-status="end.leave"） → 计划离开事件：触发：用户取消、替换目标或不可恢复失败请求 end.leave。参与者：focus transition 与 plan lifecycle。状态变化：计划成为离开终态并释放当前执行焦点。条件/例外：它不是正常完成或普通等待；不得要求任务完成、retrospective 或知识沉淀成功。证据：packages/cli/src/command-service.ts plan.leave；packages/core/src/plan.ts。
- 计划任务（status="done"） → 执行证据：触发：task.done 成功且知识 capture 处理所属执行窗口。参与者：transcript/report capture。状态变化：把成功 task.done 前最近一条 assistant checkpoint 记录为 task_conclusion。条件/例外：task.done 命令本身没有 conclusion 参数；伪文本、失败调用、越界 turn 或纯状态列表不能成为结论。证据：.claw/truth/features/cli-guided-workflow.md；.claw/truth/features/codex-knowledge-capture-boundary.md。
- 计划任务 → 计划变更：触发：task add、edit、remove 或 done 针对计划任务执行。参与者：CLI command service 与 Core editPlan。状态变化：生成带 mutationId、affected task IDs 和可选完成事件的计划变更。条件/例外：route-aware task 完成必须带合法 choice；task.done 不接受 conclusion 字段。证据：packages/cli/src/command-service.ts；packages/core/src/plan.ts。
- 会话计划绑定 → Canonical 计划：触发：context、session.open、plan sync 或 plan resume 需要恢复当前 workflow。参与者：session binding resolver。状态变化：按显式相对 planPath 读取唯一 canonical plan。条件/例外：缺失或失效 binding 表示无可恢复计划，绝不扫描 task 目录猜测。证据：packages/core/src/session-bindings.ts；.claw/truth/features/task-layout-and-session-bindings.md。
- 会话身份 → 知识收尾作业：触发：项目计划注册，或正常完成路径已经触发知识收尾。参与者：knowledge session registry。状态变化：sessionId、origin host、activeStartedAt 与 plan/report 路径限定作业身份和 capture 窗口，finalizeId 由 session、planPath 与 endedAt 确定性派生。条件/例外：会话身份只限定作业归属，不单独创建作业；缺少 sessionId、session scope 或 end.leave 均不创建新的项目知识作业。证据：packages/core/src/knowledge-sidecar.ts。
- 会话身份 → 会话计划绑定：触发：宿主以 canonical workdir 与 agent session identity 打开或恢复会话。参与者：session runtime 与 project binding store。状态变化：建立或读取该 session key 对应的零或一个 .claw 相对 planPath。条件/例外：workdir 不可在同一复合键内原地变更；连接中断不自动重放 mutation。证据：packages/core/src/session-workflows.ts；.claw/truth/features/task-layout-and-session-bindings.md。
- 工作流指引 → 宿主适配器：触发：命令 envelope 返回结构化 workflowGuidance。参与者：当前平台 adapter 与主 agent。状态变化：adapter/agent 按 stage 和 nextsteps 延续生命周期。条件/例外：adapter 不应重新从 raw plan 推导一套竞争语义，也不能过滤共享的必需收尾步骤。证据：.claw/truth/adr/codex-adapter-follows-workflow-guidance.md；.claw/truth/features/host-neutral-integration-contract.md。
- 工作流指引（stage="execution"） → 计划任务：触发：plan 位于 process.active 且仍有未完成任务。参与者：workflow guidance consumer。状态变化：返回当前或下一个可执行任务及其完成选择，使执行一次聚焦一个检查点。条件/例外：全部任务完成时不再选择新任务，而是进入 retrospective 与 plan.done 收尾。证据：packages/core/src/workflow-guidance.ts process.active 分支。
