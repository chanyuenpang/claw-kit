# smoke-test-claw-kit

确认外部用户在不同操作系统和 adapter 上能安装、加载并使用 claw-kit 的核心计划工作流。可用性包含 plan 的编辑和状态操作、task 的增删改完成、subplan 创建与返回，以及收口和退出。每个核心操作族取一个小型真实成功例；不遍历参数组合、全部模板、配置策略或错误边界。测试对象是 claw-kit，宿主只是运行条件。

## 公开环境

先读 [外部环境核验](references/environment.md)。只使用官方公开 CLI、依赖与插件；记录版本/ref、来源、实际解析路径、文件摘要和实际加载证据。禁止 workspace、npm link、file:/本地 tarball、仓库 dist、源码构建、修改 installed/cache 包、mock 宿主工具。

环境不合格时先在隔离安装/profile 中按原因修复并重验，不能直接结束或换成本地包。修复后仍缺必要条件才标记 blocked，继续其他可执行平台。来源核验只针对本轮实际调用链，不扫描整机无关包。

## 跨平台执行

1. 用 [可用性场景](references/scenarios.md) 确定操作系统 × adapter 范围。用户指定范围时照做；未指定时至少覆盖当前真实 adapter，并覆盖其他当前可准备的 adapter，列出其余组合未覆盖的原因。不要为了冒烟安装所有宿主。
2. 在仓库外创建唯一测试 project/session/runtime 与证据目录。保持公开默认行为，不通过关闭 Goal、知识收口或 hooks 掩盖链路失败。
3. 从当前公开 help、loaded skill 与 tool schema 列出核心操作，映射到场景表，再通过各平台真实路径执行。相同行为可映射为不同 operation，不能假定所有 adapter 有同名工具。Codex 使用实际加载的官方 skill 固定 code-mode driver；其他 adapter 使用官方插件入口；standard 使用公开 hostless CLI。只读 CLI help 可以辅助发现合同，不算插件操作通过。
4. 在一个小型父计划中串行验证编辑、移除、任务操作、wait/resume、恢复及 subplan；随后完成与默认收口，再用独立小计划验证取消及适用的切换。检查 canonical 状态、父子关系、当前绑定与平台声明的必要宿主效果。子计划结束后按返回合同核验父 task，已经自动完成的 task 不重复 done。需要知识处理时使用真实 writer/finalizer；只验证本次收口，不遍历策略。
5. 失败时保留原始输出和已提交状态。安装/加载条件问题先修复；claw-kit 缺陷记 failed，阻断其依赖步骤并继续其他平台。不得用直接 CLI、SDK、手工 host 参数或本地修复代替失败的插件入口。

每个核心操作族成功一次即可；支持的批量操作可减少调用，但要核对每项实际提交，不把 partial chain 当全部成功。除有依据的复现、环境修复后重验或产物变化外，不重复运行。新增公开核心操作必须映射到场景或给出不适用依据，不能悄悄漏掉。

配置组合、全部模板、多层子计划、并发压力、TTL、检索模式、知识策略排列、升级流程和系统性故障注入属于另外的功能验证。本 skill 不因发现这些入口就自动扩张范围。

## 判定与报告

每个操作系统 × adapter 单独报告 passed、failed、blocked 或有公开支持合同依据的 not-applicable。当前机器无法执行另一操作系统是 blocked/未覆盖，不能推断通过。standard 成功不能证明插件成功；宿主缺少原生 Progress 时不要求该效果，应核验 claw-kit 按平台合同正确处理。

在隔离目录保存报告与原始证据：目标版本、平台清单、环境修复/核验、核心操作到真实入口的映射、逐步输入/结果、canonical 与绑定/收口核对、失败复现和未覆盖平台。每一步记录预期和实际结果；任何 hostEffectFailures、未完成收口或绑定错误均不能判 passed。仅当声明范围内全部适用必测步骤通过，才能称该范围可用，不用全功能覆盖率评价冒烟。

只清理本轮创建且路径确认的资源，保留报告与失败现场。不发布、推送或替换真实用户配置；共享宿主重启、凭证等确实超出授权的必要条件才请求用户提供。仓库修复必须发布后再用新公开产物复跑，才能改变外部可用性结论。
