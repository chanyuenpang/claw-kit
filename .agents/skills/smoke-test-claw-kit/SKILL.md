# smoke-test-claw-kit

确认外部用户在不同操作系统和 adapter 上能安装、加载并使用 claw-kit 的核心计划工作流。可用性包含 plan 的编辑和状态操作、task 的增删改完成、subplan 创建与返回，以及收口和退出。每个核心操作族取一个小型真实成功例；不遍历参数组合、全部模板、配置策略或错误边界。测试对象是 claw-kit，宿主只是运行条件。

**跨平台指 skill 可在各平台复用，不表示一次运行遍历所有平台。** 默认范围是当前操作系统与当前会话真实 adapter。先按 using-claw-kit 的当前宿主标记和实际工具选定路由，只读该路由合同；其他平台的说明仅在该平台实际执行时使用。当前路由失败不改变宿主身份。

## 公开环境

先读 [外部环境核验](references/environment.md)。只使用官方公开 CLI、依赖与插件；记录版本/ref、来源、实际解析路径、文件摘要和实际加载证据。禁止 workspace、npm link、file:/本地 tarball、仓库 dist、源码构建、修改 installed/cache 包、mock 宿主工具。

环境不合格时先在当前宿主的隔离安装/profile 中按原因修复并重验，不能直接结束、换成本地包或换宿主。修复后仍缺必要条件才标记 blocked，继续当前范围内独立可执行的步骤。来源核验只针对本轮实际调用链，不扫描整机无关包。

## 跨平台执行

1. 用 [可用性场景](references/scenarios.md) 记录当前操作系统与真实 adapter，默认只测试这个组合。只有用户明确要求多个平台时才增加目标，各平台须在其真实宿主环境分别执行并汇总。不得自动探测、安装、启动或调用 DSH、Cindy、OpenCode、OpenClaw 等其他宿主；当前有原生 adapter 时不得额外跑 standard。
2. 在仓库外创建唯一测试 project/session/runtime 与证据目录。保持公开默认行为，不通过关闭 Goal、知识收口或 hooks 掩盖链路失败。
3. 从当前公开 help、loaded skill 与 tool schema 列出核心操作，映射到场景表，再通过各平台真实路径执行。相同行为可映射为不同 operation，不能假定所有 adapter 有同名工具。Codex 使用实际加载的官方 skill 固定 code-mode driver；其他 adapter 使用官方插件入口；standard 使用公开 hostless CLI。只读 CLI help 可以辅助发现合同，不算插件操作通过。
4. 先用独立小计划验证取消及适用的切换，再在一个小型父计划中串行验证编辑、移除、任务操作、wait/resume、恢复及 subplan。检查 canonical 状态、父子关系、当前绑定与平台声明的必要宿主效果。子计划结束后按返回合同核验父 task，已经自动完成的 task 不重复 done。完成剩余任务并保存证据、回顾与报告草稿后，最后提交父计划 `plan done`；成功后立即结束测试会话，让真实宿主进入默认 finalize 时机。
5. 失败时保留原始输出和已提交状态。安装/加载条件问题先修复；claw-kit 缺陷记 failed，阻断其依赖步骤并继续当前范围内独立步骤。不得用直接 CLI、SDK、手工 host 参数、本地修复或另一宿主代替失败的插件入口。

每个核心操作族成功一次即可；支持的批量操作可减少调用，但要核对每项实际提交，不把 partial chain 当全部成功。除有依据的复现、环境修复后重验或产物变化外，不重复运行。新增公开核心操作必须映射到场景或给出不适用依据，不能悄悄漏掉。

配置组合、全部模板、多层子计划、并发压力、TTL、检索模式、知识策略排列、升级流程和系统性故障注入属于另外的功能验证。本 skill 不因发现这些入口就自动扩张范围。

## 结束会话与 finalize

父计划 `plan done` 是测试会话的最后一个计划操作。成功后只按当前路由完成必须由前台执行的收口交接，然后立即结束本轮；依赖 Stop 的后台 finalize 不需要前台追加操作。不要再读取 context/show、写报告、创建或切换计划，也不要在该会话等待 finalizer 或通过 resume 再次触发它。

报告和前台证据在 `plan done` 前保存；终态回执由真实调用记录保留。会话结束后的 canonical、绑定和 finalize 回执可由独立外层观察只读补充，不能恢复被测会话来补报告。没有独立观察条件时，结束本轮并明确标记后台收口待观察；不要为了取得完整结论保持会话开放，也不能把尚未进入真实结束时机的等待判为 finalizer 失败。

## 判定与报告

报告当前目标的 passed、failed、blocked 或有公开支持合同依据的 not-applicable。其他平台未被指定时属于本轮范围外，不作为 blocked 或导致本轮失败，也不推断通过。显式多平台任务才逐目标报告与汇总。standard 成功不能证明插件成功；宿主缺少原生 Progress 时不要求该效果，应核验 claw-kit 按平台合同正确处理。

在隔离目录保存报告与原始证据：目标版本、平台清单、环境修复/核验、核心操作到真实入口的映射、逐步输入/结果、canonical 与绑定/收口核对、失败复现和未覆盖平台。每一步记录预期和实际结果；任何 hostEffectFailures、未完成收口或绑定错误均不能判 passed。仅当声明范围内全部适用必测步骤通过，才能称该范围可用，不用全功能覆盖率评价冒烟。

只清理本轮创建且路径确认的资源，保留报告与失败现场。不发布、推送或替换真实用户配置；共享宿主重启、凭证等确实超出授权的必要条件才请求用户提供。仓库修复必须发布后再用新公开产物复跑，才能改变外部可用性结论。
