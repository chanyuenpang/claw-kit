# planning

Write or refine an executable plan for the user's request, with a clear goal, scope, ordered tasks, and observable completion conditions.
Workflow entry and lifecycle remain the responsibility of `using-claw-kit` and returned guidance.

- Split tasks around meaningful, verifiable outcomes, not a predefined task count.
- Keep implementation, documentation, validation, and review together when they produce one outcome; separate them only for distinct downstream work, ownership, or risk boundaries.
- Do not invent speculative downstream tasks to make a plan appear complete. When the route depends on evidence, plan through the decisive checkpoint and refine the remaining work from its results.
- Record constraints, references, and decisions when they add useful execution context, so another agent can continue from the plan.
- Write plan content in the user's preferred language unless the repository has an explicit stronger convention.

A user-specified solution or a route sufficiently determined by an established workflow or available evidence can proceed without a redundant confirmation step. Before adopting another solution, ensure the user has seen its decision-relevant content; if it introduces a meaningful choice, wait for the user's response.
