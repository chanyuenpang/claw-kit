# 设计产物与门禁

按变更风险选择最小充分产物。正文优先记录决定、合同和验收；研究过程与文件清单不是默认交付物。

## 轻量架构设计

适用于单一领域内新增概念或有限的两系统协作。设计摘要包含：问题与边界、领域模型、owner 与流向、正常与关键失败合同，以及最小实现与验证。控制在一页左右，只引用会改变实现决定的少量锚点。

## 完整架构设计

适用于跨多个领域、资源/存档协议、生命周期/状态机、长期扩展机制或难逆决策。除轻量内容外，仅在必要时增加上下文图、可行替代方案和演进策略。不要把 UI 或外部存储画成业务事实 owner。

## 证据与完成标准

- 每段至少回答：为什么这样做、谁拥有事实、失败时什么保持不变、如何验证；否则删除。
- 先列待决策问题，再定向取证；确认结论后停止扩展检索。
- 另一位开发者只读设计即可定位 owner、拒绝越界写入、解释关键失败状态并执行最小验证时，设计即足够。
